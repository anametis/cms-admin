# Folio Studio

A small editorial workspace built with React, Vite, TanStack Router, and TanStack Table. Its UI and responsive layout are adapted from **[shadcn-admin by Sat Naing](https://github.com/satnaing/shadcn-admin)**, with Folio branding and Base UI primitives.

The story library is sample data. There is no backend, authentication, or publishing workflow.

## Quick start

Use Node.js 22.19 or newer and npm.

```sh
npm ci --include=dev
npm run dev
```

Open the URL printed by Vite, usually `http://localhost:5173`.

Both `package-lock.json` and `pnpm-lock.yaml` are maintained. npm is the documented installation path; pnpm users can run `pnpm install --frozen-lockfile`. Keep both lockfiles current when changing dependencies.

## What is included

- An overview with story counts, a review queue, and recent stories.
- A content list with search, status filters, and date sorting stored in the URL.
- Read only story details, plus loading, error, missing page, and empty states.
- A collapsible desktop sidebar and mobile navigation sheet, with Ctrl/Cmd+B support.
- Light, dark, and system themes, with locally bundled DM Sans and Outfit fonts.
- Storybook examples for the shared UI components.

### Browser checks

These optional checks use the `agent-browser` CLI. Install it once with `npm install -g agent-browser`, then run `agent-browser install`. Start the app before running:

```sh
npm run test:browser
node tests/ui-migration.mjs
node tests/post-table.mjs
```

They cover mobile focus return, Base UI interactions, and table behavior. Each accepts an app URL as its first argument, for example:

```sh
node tests/post-table.mjs http://127.0.0.1:4173
```

Browser checks are separate from `npm run check`, so ordinary checks do not require a browser.

## Component development with Storybook

```sh
npm run storybook
```

Open the URL printed by Storybook, normally `http://localhost:6006` (it chooses another port if that one is occupied). Each of the 11 current UI wrappers has examples, with controls and generated documentation. The theme toolbar lets you inspect light and dark appearances using the same CSS tokens and fonts as the app. Use the viewport toolbar for responsive layouts, especially the sidebar's mobile sheet.

**You set up Storybook once, not once per component.** When you add a component manually, add a neighboring `component-name.stories.tsx` file. The `src/**/*.stories.tsx` pattern discovers it automatically. You only need to change Storybook configuration when a new component needs additional shared context, styling, or an addon.

A minimal example:

```tsx
import type { Meta, StoryObj } from '@storybook/react-vite'
import { Button } from './button'

const meta = {
  title: 'UI/Button',
  component: Button,
  args: { children: 'Save story' },
} satisfies Meta<typeof Button>

export default meta
type Story = StoryObj<typeof meta>

export const Default: Story = {}
export const Disabled: Story = { args: { disabled: true } }
```

The existing compound stories show how to include providers, labels, triggers, and popup content. Storybook has an isolated Vite configuration, so viewing a component does not boot the CMS router or regenerate routes.

## shadcn and Base UI

Components live in `src/components/ui/` and are maintained as source code, not an external theme package. Interactive primitives use `@base-ui/react`; native wrappers such as card, input, and table stay native. The `@/` alias resolves to `src/`.

**Registry warning:** `components.json` still uses the legacy `new-york` style to preserve the app's appearance. That style has no matching Base variant, so ordinary `shadcn add` commands still generate Radix primitives. Add explicit Base variants and preserve local styles, or deliberately choose a new Base style before adding interactive components. The same warning applies to MCP generated add commands. Migration details are in `.migration/`.

### Linting

[`@shadcn/lint`](https://github.com/shadcn-ui/lint) is installed and registered with Oxlint in `.oxlintrc.json`. **No `shadcn/*` rules are enabled yet.** To enable design system enforcement, add the rules you want to that file; no second linter is needed. See the [rule reference](https://github.com/shadcn-ui/lint#rules).

### shadcn MCP in Pi

`.pi/mcp-adapter.json` configures `npx -y shadcn@latest mcp` for the installed Pi MCP adapter. Run `/reload` in Pi and approve the project server if prompted, then inspect it with `/mcp-adapter`. It offers registry discovery, search, examples, and add commands. The standard registry needs no API key; existing global MCP servers are unchanged.
